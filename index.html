⚡ omarchy-cluster - Run One AI Model Across Your Macs

One local model, many computers, one simple address.

omarchy-cluster lets you take a single local machine learning model and spread it across more than one Apple Silicon Mac running macOS, and across machines running Omarchy Linux. Instead of your model living on one computer, it works together across the group. When it is running, everything is reachable through one address that behaves exactly like the familiar OpenAI-style service that many apps already know how to talk to.

No programming knowledge is needed to get started. If you can download a file and follow a short list of steps, you can have this running.

Download omarchy-cluster

🚀 What This App Actually Does

Think of a large AI model as a long book that is too heavy for one person to carry. omarchy-cluster splits that book into chapters and hands a chapter to each computer in your group. Each computer only holds a smaller piece, so together they can run a model that would be too big for any single machine on its own.

The clever part is that you never have to manage this split yourself. You start the app on each computer, tell them about each other once, and the whole group presents itself as a single service with a single web address. Any app, tool, or script that already works with an OpenAI-compatible endpoint can point at that address and simply work, without knowing that several computers are involved behind the scenes.

Everything stays on your own hardware and your own network. Your questions and your model's answers do not travel to a company server somewhere else.

✨ Key Features

One address for everything The whole group of machines answers at a single OpenAI-compatible endpoint, so your existing apps do not need to change.
Built for Apple Silicon Uses the MLX framework, which is designed specifically to get the most out of the chips inside modern Macs.
Mix Macs and Linux Run on macOS machines and on Omarchy Linux machines in the same group, with Vulkan graphics support on the Linux side.
Pipeline parallelism The model is divided into stages and passed from machine to machine, which is what lets a group outperform a single device.
Local and private Your prompts and responses stay on the machines you control. Nothing is uploaded anywhere.
Familiar interface Because the endpoint speaks the OpenAI format, existing tools, chat front-ends, and scripts plug straight in.

💻 What You Need Before You Start

  • At least one supported computer. Either an Apple Silicon Mac running macOS, or a computer running Omarchy Linux.
  • A local network. The computers need to be able to reach each other. Being on the same home or office Wi-Fi or wired network is enough.
  • Enough free storage. The model files are large, and each machine in the group needs room for its own share of the work.
  • A model file you want to run. The download page explains which model formats are supported.
  • A little patience the first time. The first start is always the slowest, because files have to be prepared. Later starts are much quicker.
Adding a second or third computer is optional at first. You can start with one machine, confirm everything works, and grow the group afterwards.

⬇️ Download And Setup

The download is handled entirely through the project page. Visit this link to download the application.

Visit this link to download the application

Once the page opens, you will see the files and notes for the current release. Read the short description next to each file, pick the one that matches the computer you are setting up, and save it to a folder you can easily find again, such as your Downloads folder.

Step by step

  1. Open the download page. Use the button above. It takes you to the official project page where the application lives.
  2. Choose the file that matches your computer. The page groups files by operating system. If you are on an Apple Silicon Mac, choose the macOS file. If you are on Omarchy Linux, choose the Linux file.
  3. Save it somewhere you will remember. Your Downloads folder is fine. Avoid saving inside a temporary folder that gets cleaned automatically.
  4. Repeat for each computer you want in the group. Each machine needs the application, but only one copy is needed per machine.
  5. Note the network address of your first computer. The page explains where to find it. You will type this address into the other machines later.
  6. Start the application on the first computer. Follow the short instructions shown on the download page for your system. Leave it running.
  7. Start the application on the next computer and point it at the address you noted in step five. The group will introduce itself automatically.
You only need to do the setup once per computer. After that, starting the group is a single action you can repeat any time.

🖥️ Your First Run

When the group starts for the very first time, expect a wait. The application needs to read the model files, divide the work between machines, and confirm that every computer is reachable. Small lights or status lines on screen will tell you how far along it is.

When it finishes, the application reports the single web address where your group is answering. It typically looks like a normal local address followed by a port number. Copy that address down. This is the one thing every other app will need.

To confirm everything is healthy, send a simple test message through the address the application shows. A short, sensible reply means the group is working correctly and you can start using it properly.

🔌 Using It With Your Own Apps

Because the group answers in the OpenAI-compatible format, connecting a program is usually just a matter of pasting two things into its settings screen:

  • The base address shown by omarchy-cluster when it starts.
  • A key field. Local setups commonly accept any placeholder text here. If the app insists on something, type a short word such as local.

After saving those settings, the app will send its requests to your own machines instead of the internet. Nothing else about how you use that app changes.

🧩 Common Questions

Do I need more than one computer?

No. A single machine works fine and is the easiest way to try things out. Adding machines is what lets you run larger models than one computer could handle alone.

Can I mix an Apple Silicon Mac with an Omarchy Linux machine?

Yes. That mix is exactly what the project is designed for. Each machine runs the version built for its own operating system while the group behaves as one.

Does my data leave my network?

No. The models run on your hardware and requests travel only between your own machines.

Do all the computers need the same amount of memory?

Not necessarily, but the group can only go as fast as its slowest member. Machines with similar capabilities tend to work together most smoothly.

What happens if one computer disconnects?

The group needs all of its members to answer. If a machine drops off the network, reconnect it and restart the group.

🛠️ If Something Goes Wrong

  • The group never finishes starting. Check that every computer is awake, on the same network, and has the application running.
  • One machine is not recognised. Re-check the address you typed. A single wrong digit is the most common cause.
  • Responses are very slow. Close other heavy programs on each machine, especially anything using the graphics processor.
  • An app cannot connect. Confirm you pasted the full address including the port number, and that the group is still running.
  • Storage warnings appear. Free up space and start again. Model files need a lot of room.

🔐 Privacy And Control

omarchy-cluster runs entirely on hardware you own. There is no account to create, no sign-in, and no cloud service in the middle. You choose which model to load, which machines take part, and when the group runs. When you stop the application, nothing keeps running in the background.
